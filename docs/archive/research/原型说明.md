# 原型：MRQ 个人财报系统（hledger + deg 薄壳）

## 一句话

用现成的 `double-entry-generator` 把支付宝/微信/银行账单翻译成 hledger 复式账本，
用现成的 `hledger` 生成四期财报（一季报/半年报/三季报/年报，累计口径），
本目录只是"胶水"脚本，不实现任何会计引擎。

## 目录

```
prototype/
├── config/
│   ├── alipay.yaml        支付宝账单→账本 规则（初版，基于真实账单统计）
│   ├── wechat.yaml        微信账单→账本 规则（初版）
│   └── 科目表草案.md      五大要素科目 + 期初建账模板
├── journals/              账本纯文本（UTF-8；git 可追溯 = 审计日志）
│   └── 2026.journal       全年演示账本（权责发生制+折旧摊销+花呗）
├── raw/                   放原始账单（敏感，不入 git；也可只引用外部路径）
├── close/                 结账快照与留存收益结转分录（反结账=删除对应文件）
├── reports/2026/          四期财报（txt/html/csv + 汇总 PDF）
└── scripts/finance.py     编排器：import / check / report / close / reopen
```

## 用法

```bash
# 校验账本平衡
python scripts/finance.py check

# 导入账单（把原始账单放进 raw/，或修改 finance.py 中的路径指向外部目录）
python scripts/finance.py import

# 生成 2026 年 Q1/H1/Q3/年报 五件套（含 PDF）
python scripts/finance.py report 2026

# 结账 / 反结账（结账=账本快照+生成留存收益结转分录；反结账=删除该期结转）
python scripts/finance.py close 2026 Q1
python scripts/finance.py reopen 2026 Q1
```

## 关键设计（对应访谈决策）

| 决策 | 实现 |
|---|---|
| 真复式记账 | hledger 引擎：每笔交易必须平衡，`check` 校验 |
| 模板快捷记账 + 完整凭证 | 日常=deg 规则自动生成；专业分录=直接编辑 journals/*.journal |
| 期初建账制 | 盘点余额写一条期初分录，差额进 `Equity:期初调整` |
| 待确认队列 | `Assets:FIXME` / `Expenses:FIXME` 账户余额即"待确认清单" |
| 完全权责发生制 | 工资月末计提 `Assets:应收账款:工资`，到账冲销；房租预付+月摊销 |
| 自动计提/折旧 | 在 journal 里写 hledger 定期规则 `~ monthly`，报表加 `--forecast` |
| 花呗负债真实入账 | deg `method: 花呗 → Liabilities:花呗`；还款流水自动冲负债 |
| 投资成本+公允价值 | journal 记录成本；`balancesheet -V --value=end` 出市值；或每期末手工调账 |
| 四期财报累计口径 | `report` 分别取 03-31 / 06-30 / 09-30 / 12-31 截止 |
| 结账快照+反结账 | `close`=快照+close 分录文件；`reopen`=删除 close 文件（纯文本天然可逆） |
| 现金流量表直接法 | `cashflow`（现金类科目）；账户间调拨不计入 |
| PDF 导出 | hledger `-O html` + Edge headless `--print-to-pdf` |
| CSV 导出 | hledger `-O csv`（本脚本已生成） |

## 已知限制（诚实披露）

1. **Windows 编码**：hledger 需 UTF-8 代码页；脚本自动 `chcp 65001`。账本保持 UTF-8。
2. **组合支付方式**：支付宝"余额宝&花呗"等混合支付，deg 只能整笔记一个账户
   （当前规则让花呗优先），需少量人工拆分；可在 deg 上层加预处理或提 PR 支持拆分。
3. **现金流量表**：hledger 的 `cashflow` 是"简单现金流量表"（按现金账户列示），
   经营/投资/筹资三段式需要按账户命名约定 + `balance` 查询组合生成（壳层可加）。
4. **所有者权益变动表**：用 `balancesheetequity` + `close --retain` 的留存收益变动体现，
   完整四列表需壳层从 Equity 账户 register 汇总。
5. **微信 xlsx**：需为真实导出格式（金额列为数字）；deg 的示例 xlsx 用引号字符串会失败，
   真实账单实测通过。
6. **PDF**：依赖 Edge headless（本机已验证）；如需无浏览器环境可换 wkhtmltopdf。
