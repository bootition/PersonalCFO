# 研究报告 v3 · 定稿（用户裁决后的开发总纲）

- 日期：2026-09-06
- 状态：**当前权威版本**；取代 `研究报告_选型结论.md` 与 `研究报告_第二阶段补全_Wealthfolio与需求补全.md`（两版保留为调研过程档案）
- 原则：**拿开源工具来改造，而不是硬拼接**——每个组件都必须被"改成我们的"，共享同一视觉语言、同一数据源、同一操作入口

## 1. 一句话架构

**hledger 管账、deg 管导入、Wealthfolio 管投资与目标、Paisa（改造版）管日常界面；四者围绕一个纯文本 journal 仓库运转，财报由 hledger 唯一出数。**

## 2. 总体架构

```
┌──────────────────────────── 数据源（本地，敏感） ────────────────────────────┐
│ 支付宝CSV │ 微信XLSX │ 花呗月账单 │ 银行卡明细(建行/工行/招行/光大) │ 投资平台交易记录 │
└──────┬──────────┬──────────┬────────────┬──────────────────────┬───────────┘
       │          │          │            │                      │
       ▼          ▼          ▼            ▼                      ▼
   ┌─ deg translate（YAML规则）──┐   ┌── Wealthfolio（投资子账本）──┐
   │  账单→journal；花呗拆分脚本  │   │ 逐笔交易/持仓/净值/目标/FIRE │
   │  （组合支付按花呗账单拆分）   │   └──────────┬─────────────────┘
   └──────────────┬──────────────┘              │ 季度 holdings.csv / API 导出

        ┌─────────────────────────────────────────────────────┐

        └──────┬───────────────────────┬───────────────────────┘
               │                       │
               ▼                       ▼

        · 现金流预测             · 导入与对账入口（调 finance.py）
        · PDF/CSV 导出           · 预算（二期再启用）
        · 月度账实核对清单

               ▼
```

## 3. 组件职责与边界（谁干什么、不干什么）

### 3.1 hledger（会计核心，抄来即用 + 壳层扩展）
- 干：复式分录校验（check）、五张财报（资产负债表/利润表/现金流量表/含权益资产负债表/权益变动）、季度累计口径（Q1=1-3月、H1=1-6月、Q3=1-9月、年报）、`close --retain` 结账与反结账、`~` 定期规则（工资计提、折旧、房租摊销）、`--forecast` 现金流预测、CSV/HTML 输出。
- 不干：不做 GUI；不存数据库（账本就是文件）。
- 边界：**唯一会计真相**。任何数字冲突，以 journal 为准。

### 3.2 deg（账单导入桥，抄来 + 两个改造）
- 干：支付宝 CSV、微信 XLSX、建行/工行/招行/光大等银行明细 → ledger/hledger journal；规则（字段/商户/商品/支付方式/金额/时间 → 科目）；退款反向匹配；支付方式→花呗/银行卡科目。
- 改造点 1：**花呗组合支付拆分脚本**——用户每月开具花呗账单，脚本按订单号/商户/金额+日期把 `余额宝&花呗`、`花呗&红包` 等组合支付拆成两条分录（花呗承担额→`Liabilities:花呗`，其余→对应资产/费用科目）。
- 改造点 2：deg 规则 YAML 按真实账单迭代（首版已在 `prototype/config/`）。
- 不干：不猜无法确定的交易——全部落 `*:FIXME` 科目，FIXME 余额即待确认队列。

### 3.3 Wealthfolio（投资子账本 + 目标规划，引入 v1）
- 干：**投资逐笔交易只记这里**（股票/基金/虚拟货币/CS饰品）；持仓/净值/配置目标与再平衡/绩效（顺带可用）；**目标规划**（应急金、攒股等目标）；FIRE 模块（白送，想看就点）；市场数据自动更新；UI 美观。
- 与 hledger 的关系：**子账本模式**——hledger 投资科目只记"期初成本 + 每季度一条净值变动分录"，分录数字由 Wealthfolio 导出的 holdings.csv 自动生成。投资组合因此成为财报资产负债表与利润表的一部分，且**不双录**。
- 不干：不管现金/消费/负债/计提/折旧；不生成三张财报；Connect 订阅不买（本地手动导入）。

### 3.4 Paisa Fork（统一日常 UI，选定底座，深度改造）
- 拿 Paisa 改：修 hledger `--commodity-style` bug（`internal/ledger/ledger.go:205`）→ 中文化（i18n 加 zh）→ **换 Wealthfolio 视觉风格**（配色/字体/卡片/圆角/间距设计令牌）→ 顶栏挂"导入、财报、结账、对账"入口（调 finance.py）→ 启用账单/还款日历。
- 干：查流水、编辑 journal（语法高亮/自动补全）、FIXME 待确认清单、账单日历、预算（**二期才启用**）、图表。
- 不干：不自己算财报（财报页只展示 finance.py 生成的 PDF/CSV 与 hledger 报表）。

## 4. 组件之间怎么联系（七条数据流）

| # | 数据流 | 触发 | 格式/内容 |
|---|---|---|---|
| F1 | 支付宝/微信 → journal | 每周/每月导入 | deg `translate -t ledger`，UTF-8 journal；退款自动反向；未命中→`*:FIXME` |
| F2 | 银行卡明细 → journal | 每月导出后导入 | deg 银行 provider → 银行卡科目；与 F1 同源同账 |
| F3 | 花呗月账单 → journal | 每月随支付宝一起导入 | 拆分脚本：把 F1 中组合支付行拆为 `Liabilities:花呗` + 其余科目两条分录 |
| F4 | 投资交易 → Wealthfolio | 交易发生时（低频） | 只在 Wealthfolio 录入（Transactions 模式） |
| F5 | Wealthfolio → journal | 每季度结账前 | `finance.py sync-fair-value`：读 holdings.csv（市值/成本/浮盈）→ 生成 hledger 调整分录（借/贷投资科目，贷/借`Income:投资损益:公允价值`）→ 财报投资数字与 Wealthfolio 一致 |
| F6 | journal → 财报 | 每季度末 | `finance.py report`：hledger 生成五张财报（累计口径）+ 指标摘要（规模结构/盈利增长/现金结余/**应急金覆盖月数**）+ 现金流预测（`--forecast`）→ PDF/CSV |
| F7 | journal → Paisa UI | 实时 | Paisa 以 `ledger_cli: hledger` 直读 journal（只读为主）；编辑器改动直接写 journal；结账入口调 F6 |
| F8 | 账实核对 | 每月 | `finance.py reconcile`：列出各科目账面余额 vs 手动录入真实余额 → 差异清单 → 出调账分录；花呗/银行卡靠 F2/F3 自动对账，现金靠手动 |

**一笔业务的完整旅程（示例：花呗+红包组合消费 20 元）**
支付宝 CSV 一行 `花呗&红包 20` → F1 标记组合支付 → F3 用花呗账单查到"花呗承担 15" → journal 生成：`借 Expenses:日常娱乐 20 / 贷 Liabilities:花呗 15 / 贷 Income:其他收入:红包 5`（红包是平台补贴）→ Paisa 立即可查 → 季度末 F5/F6 把它纳入财报费用与负债 → 月度 F8 花呗余额自动核对。

## 5. v1 决策清单（本次弹窗裁决 + 沿用此前访谈）

**本次新裁决（2026-09-06）**
- D-A1 Wealthfolio 引入 v1：目标规划 + 资产/净值 UI + 投资组合；绩效分析顺带可用，不作为主线。
- D-A2 投资数据流：**Wealthfolio 子账本**（F4/F5），hledger 只记期初+季度调整，零双录。
- D-A3 UI 底座：**Fork Paisa 深改**——修 bug → 中文化 → Wealthfolio 风格 → 挂入口；统一美观，不硬拼。
- D-A4 预算：**先观察不设**，1-2 个季度财报环比后再定预算线。
- D-A5 银行卡：**v1 纳入**（用户可从各银行 App 导出明细）。
- D-A6 花呗：**每月导出花呗账单，精确拆分组合支付**（需用户先提供一份样例验证格式）。
- D-A7 财报输出：只 PDF/CSV，**不做 Markdown 归档**。
- D-A8 纳入：账单/还款日历、现金流预测、应急金覆盖月数 KPI、FIRE 模拟（Wealthfolio 白送）、git 私库备份。
- D-A9 不纳入（二期/远期）：预算、税务参考、AI 本地预分类、手机端访问、目标储蓄专用科目。

**沿用此前 grill 结论（未改变）**
- 真复式记账；预置科目表+可扩展；期初建账制；FIXME=待确认队列；完全权责发生制（仅工资计提）；每月自动折旧摊销；花呗/银行卡/信用卡负债真实入账；货币基金=现金等价物；四期财报累计口径+五件套；结账快照+可反结账；现金流量表直接法；社保公积金不入表；存量固定资产历史原价；月度账实核对；本地单机无云。

## 附录 A：四个工具到底怎么"拼"成新工具（组合原理）

先纠正一个理解偏差：**我们不是在把四个工具的代码揉成一个新程序**。新工具 = 一个纯文本账本（唯一真相）+ 四个开源工具各干一摊 + 一小撮我们自己写的"胶水"。介入深度分四档：

### A1. 原样使用（零改代码）——hledger、deg、Wealthfolio

| 工具 | 介入方式 | 我们动的东西 |
|---|---|---|
| hledger | 二进制原样跑（`tools/hledger-bin`） | **只写配置**：科目表、`~` 定期规则、结账命令；它是引擎，不是被改的对象 |
| deg | 二进制原样跑 | **只写 YAML 规则**：支付宝/微信/银行的字段→科目映射；花呗拆分是"外面加的预处理脚本"，不动 deg 源码（以后要提 PR 再说） |
| Wealthfolio | 装官方应用 | **只录数据**：投资交易、目标配置；它的 CSV/REST 导出当接口用 |

> 类比：hledger 是发动机（整个拿走），deg 是进气管（整个拿走，换滤芯=规则），Wealthfolio 是仪表盘（整个拿走，我们给它接数据线）。

### A2. Fork 改造（改代码）——只有 Paisa 一个

| 改造点 | 工作量 |
|---|---|
| 修 hledger `--commodity-style` 参数 bug（1 行） | 1 行 |
| 中文化（它自带 i18n，加 zh 翻译文件） | 翻译表 |
| 换 Wealthfolio 风格（两家都是 Tailwind，改设计令牌=配色/字体/圆角/间距） | 机械替换 |
| 顶栏挂"导入/财报/结账/对账"按钮（调 finance.py） | 少量 Svelte 页面 |

> 这一步是"换壳改色"：拿现成的仪表盘样式和现成的账本界面，改成一套统一好看的门面。AGPL 本地自用没有开源义务。

### A3. 自写胶水（真正的新代码，约几百行）——finance.py + 拆分/回写脚本

| 脚本 | 干什么 |
|---|---|
| `import` | 调 deg 跑各账单 → journal；调花呗拆分脚本 |
| `split-huabei` | 用花呗 PDF 把组合支付拆成两条分录（新代码） |
| `report` | 调 hledger 出四期五件套 + 指标摘要 + Edge PDF（原型已跑通） |
| `sync-fair-value` | 读 Wealthfolio holdings.csv → 生成季度净值变动分录 |
| `close/reopen` | 结账快照 + 反结账 |
| `reconcile` | 月度账实核对清单 |

### A4. 数据契约（让四者咬合的不是代码，是文件）

| 文件 | 谁写 | 谁读 |
|---|---|---|
| `journals/*.journal` | deg / 拆分脚本 / sync 脚本 / Paisa 编辑器 | hledger、Paisa、finance.py |
| `config/*.yaml` | 我们（deg 规则） | deg |
| Wealthfolio `holdings.csv` | Wealthfolio 导出 | `sync-fair-value` |
| 花呗 PDF | 支付宝 | `split-huabei` |
| 财报 PDF/CSV | finance.py | 人 / Paisa 展示 |

> 核心一句话：**咬合点是"文件"不是"代码"**——journal、YAML、CSV、PDF 就是接口；四个工具各自独立演进，坏了一个换一个，账本永存。

## 附录 B：花呗账单样例结论（2026-09-06 实测）

文件：花呗账单证明 PDF 样例（路径与打开密码见本地文件 `docs/本地敏感信息_DO_NOT_COMMIT.md`，不入库；pypdf 解密验证成功，17 页）。

- 结构：2026-02 ~ 2026-09 八个 `YYYY年MM月_花呗账单` 分段；每行 = 时间（日期+跨行秒）、名称、状态、金额、手续费。
- 字段可用性：
  - **名称**与支付宝 CSV 的商品说明基本一致（如"美团订单-美团骑行-单车-骑行费-2026-06-06"），可匹配；
  - 名称内常嵌**美团 26 位单号**（`2606031110030000130829...`），对应支付宝的商家订单号，可精确匹配；
  - `**单号XP...` 为脱敏单号，退而按"日期+金额+名称"模糊匹配；
  - `自动还款 -999.19`、`退款还款 -18.1` 让还款/退款冲销也能自动生成分录。
- 结论：**可用，组合支付精确拆分可行**；拆分脚本按"美团单号 > 日期+金额+名称"两级匹配，P1 实跑验证匹配率（目标 ≥95%，未匹配进 FIXME）。
- 注意：文件含身份证号，仅本地使用，勿提交 git、勿外发。
