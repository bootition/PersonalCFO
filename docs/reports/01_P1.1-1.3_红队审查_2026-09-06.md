## 2. P0 发现与修复

### R3 货币基金"收益发放"方向系统性反转 ✅ 已修复
- **发现**：447 笔每日收益（源账单标"不计收支"）被记成 借 Income:利息收入 / 贷 余额宝，方向 100% 相反（合计 61.32 元；余额宝累计低估 122.64 元）。根因：deg 语义下 `targetAccount` 对"不计收支"落借方，L3 利息收入规则不适用此类。
- **修复**：`config/alipay.yaml` L6 新增矫正规则（`type: 不计收支 + item: 收益发放` → `targetAccount: Assets:现金:余额宝` + `methodAccount: Income:利息收入`）。
- **验证**：重跑后抽查为 借 余额宝 / 贷 利息收入；`hledger balance Income:利息收入` = **−61.32 CNY**（贷方净额，符号正确，与红队数字一致）。

### R1 deg 二进制静默吞掉支付宝 CSV 首行数据 ✅ 已修复
- **发现**：deg v2.15.1（d93c79d）探针实证丢失表头后第一行（约 87 元转账）；且执行二进制与 `reference/` 源码快照（639ea22）**版本不一致**，provider 层"读源码得结论"方法存在版本风险。
- **修复**：`finance.py` 对支付宝 CSV 预处理插入**献祭占位行**（状态=交易关闭，被吞即止血，未被吞也会被 L0 规则丢弃）。
- **验证**：重跑后 journal 由 1956 → **1957** 笔（被吞行救回）；献祭行确认被吞；行数归因未解释 = 0。

### R2 冒烟归因错误（解释性假完成） ✅ 已修复
- **发现**："差异 61 行=剔除"实为 60 剔除 + 1 解析丢失——数字对、解释错。
- **修复**：冒烟改为**精确归因**：源 orderId 集合 − journal orderId 集合 = 被剔行，按状态分项（关闭/撤销/退款行/配对原单/未解释）。
- **验证**：支付宝 剔除 60 = 交易关闭×41 + 退款行×15 + 配对原单×3 + 已撤销×1，**未解释 0**；微信 剔除 29（全退款类），**未解释 0**。

## 3. P1 口径问题 ✅ 已修复

- **发现**：FIXME 占比只报金额口径（对自己有利）：支付宝笔数口径 15.07% vs 金额 4.06%；微信 13.75% vs 16.71%。
- **修复**：冒烟报告双口径并列披露（笔数占比 + 金额占比），阈值判定仍按计划口径（金额占比 <5%）。
