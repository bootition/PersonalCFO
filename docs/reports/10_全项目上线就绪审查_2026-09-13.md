## 3. 未完成的开发空白

### 3.1 P0 级空白（代码审查发现的正确性缺陷）

**P0-A `finance.py report` 不校验"期次末是否晚于期初日"→ 已产出的 2026 一季报/半年报是无意义数字，且任何自检都发现不了**

- 位置：`src/finance.py:478-528`
- 证据：本期初分录日期 `journals/2026-09-10-opening.journal`，但 `report(2026)` 无条件出 Q1（`-e 2026-04-01`）/H1（`-e 2026-07-01`）
  ```
  hledger balancesheet -b 2026-01-01 -e 2026-07-01
    Assets:FIXME -2,947.81 / 现金:支付宝 -10,076.32 / 银行存款:建设银行 -36,513.94
    Net: -46,284.78            ← 「2026 半年报」净资产为负 4.6 万
  ```
- **为什么自检抓不到**：`equity_change_table` 的内部恒等式（期末 = 期初 + 净利润 + 其他变动）在任意时点都**恒等于 0.00**，它不是正确性校验，只是算术自洽校验。
- 文档侧其实已经知道却未落地：`docs/STATUS.md`（P7.16）写"首个结账期须晚于期初"，但 `docs/runbooks/01:90` 仍直接让用户跑 `report <年>`，`STATUS.md` 还把"财报 4 份 PDF"当作完成证据。
- 修法：读 `journals/*-opening.journal` 推出期初日，`end <= opening_date` 时警告或 `sys.exit`（加 `--allow-pre-opening` 显式放行），并把期初日写进报告首页。约 2 h。

**P0-B `backup.py backup --keep 0` 会删掉刚写出的归档，同时打印"✅ 备份完成"**

- 位置：`scripts/backup.py:173`（调用）、`:177-185`（`_prune`）
- 根因：`_prune` 的候选集包含刚写出的这一份，`to_delete = archives[keep:]`，`keep=0` → 全删。帮助文本"0=不保留历史"容易被理解为"只留当前这份"。
- 实测（沙箱 mock `BACKUP_DIR`）：3 份归档 → `_prune(0)` 后 `after = []`。
- 修法：新归档排除出淘汰集（`archive.resolve() != out.resolve()`）或 `max(1, args.keep)`；sha256 打印挪到 prune 之前。约 0.5 h。

### 4.2 P1 编码缺陷：11 个脚本里只有 `finance.py` 有 UTF-8 兜底

- 唯一有 `sys.stdout.reconfigure(encoding="utf-8")` 的是 `src/finance.py:24-28`。
- **实测（本次复核）**：
  ```
  venv/Scripts/python.exe -c "import sys;print(sys.stdout.encoding)"   → gbk
  venv/Scripts/python.exe scripts/reconcile-check.py --allow-no-api | tail
    UnicodeEncodeError: 'gbk' codec can't encode character '\u2705' in position 17
  ```
- **触发条件要说清楚**：交互式终端里正常（Python 走 WriteConsoleW），**一旦 stdout 被重定向/管道/被其他程序捕获就按 CP936 编码 → 崩溃**（`chcp 65001` 对管道无效，实测先 chcp 仍崩）。
- 受影响点：`reconcile-check.py:258,259,268,274,278`、`backup.py:100,167,172,216,225,228,252`、`e2e-sweep.py:285,287`、`import_bank.py:39,52,60`。
- **实际危害**：
  - `backup.py verify` 在 `:216` 崩 → `docs/runbooks/01:79-80` 的验收流程走不通，`:217-225` 的"恢复演练 hledger check"永不执行；

- 修法：抽 `src/_console.py`，各入口调用（约 1 h）。

### 6.1 首次使用旅程：认知负担过高

**新人真实步骤（读完 README + 4 个 runbook 才能拼出来）**：装 git → clone → 读表格才知道哪些目录"不入 git" → 手工下载 hledger(73MB)/deg(10MB) → **发现还缺 paisa server 二进制且没有任何文档说它从哪来（fork 在私有仓）→ 旅程终止** → 装 Python 依赖（无 requirements）→ 自建 `paisa_test/paisa.yaml` + `all.journal` → 各 App 导出账单 → 打开 6500 → 四步向导 → 期初余额（负债填负数）→ ……

## 7. 开源发布标准（"能不能把链接发出去"）

### 7.1 法律与许可：**头号阻塞**

- **主仓无任何 LICENSE / COPYING / NOTICE**（`ls LICENSE* COPYING* NOTICE*` 全部 No such file；`git ls-files | grep -i licen` 为空）。
- **后果**：公开仓库无 LICENSE = **默认著作权全保留（All Rights Reserved）**。别人不能合法修改、分发、商用；GitHub 页面也不会显示 License 徽章。
- **组件许可证核实**：Paisa fork = **AGPL-3.0**（`vendor/paisa/COPYING`）；hledger = **GPL-3.0**；double-entry-generator = **Apache-2.0**；Wealthfolio = **AGPL-3.0**；tzdata（唯一跟踪的二进制）= Apache-2.0。
- **`src/*.py` 调用 GPL 二进制不构成衍生作品**（GPLv3 §0"运行不受限" + §5 末段 mere aggregation + 完全自写的进程接口）。**三个反转边界**必须写进 NOTICE：① 改成库链接/FFI 会传染；② 把上游源码片段 copy 进 `src/` 会传染；③ **一旦随 Release 分发 `hledger.exe`/`deg.exe`，就触发 GPL-3.0 §6 的分发义务**（与自己的代码是否衍生无关）。
- **真正的窟窿**：AGPL-3.0 §6 要求提供 Corresponding Source **且不得限制再分发**，而 fork 源码放在**私有仓** `bootition/PersonalCFO-paisa` → 不满足 §6；`vendor/paisa/paisa.exe` 的 buildinfo 是 `vcs.modified=true`（**从无一个 exe 由干净提交构建**），对应源码实际上不存在；AGPL §5(a) 要求的"修改版显著声明"也没有（`go.mod` module 路径仍是上游）。
- **推荐主仓许可证：`AGPL-3.0-or-later`**（旗舰交付物本身就是 AGPL；GPL-3.0 与 Apache-2.0 均与 AGPL 兼容；与"数据归自己"的项目叙事自洽）。选 MIT 需要额外满足"fork 永久拆成独立公开仓 + Release 永不附带 AGPL/GPL 二进制"两个前提。
- 无论选哪个，都要补 `THIRD-PARTY-NOTICES.md`（hledger / deg / Paisa fork / tzdata / Python 依赖 / Edge 六条）。
