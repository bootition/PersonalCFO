# 文件契约

> 四组件咬合靠文件不靠代码（`docs/decisions/01_架构总纲_v3定稿.md` 附录 A4）。
> 本文件以**实测**为准记录各契约格式；任何格式变化先改本文件，再改读写它的代码。
> 红线：本文件只描述结构与字段，示例一律脱敏/虚构，禁止贴真实交易。

## C1 `journals/*.journal`（hledger journal，唯一会计真相）

- **写方**：deg（import-*）、split_huabei.py（花呗拆分）、sync_fair_value.py（季度回写）、手工（期初/调整）、Paisa 编辑器
- **读方**：hledger、finance.py、Paisa
- 编码 UTF-8；Windows 下必须经 finance.py（自动 `chcp 65001`）调用 hledger。
- 分录格式（ledger 风格，deg 实测输出）：

```
2025/08/05 * <交易对方> - <商品说明>
    ; category: "<交易分类>"
    ; method: "<支付方式，含卡尾号，如 中国XX银行储蓄卡(1234)>"
    ; orderId: "<订单号>"
    ; payTime: "2025-08-05 20:32:35 &#43;0800 CST"
    ; source: "支付宝"
    ; status: "交易成功"
    ; type: "<支出|收入|不计收支>"
    Expenses:FIXME      100.00 CNY
    Assets:银行存款:建设银行   - 100.00 CNY
```

- deg 会在文件头生成 `1970/01/01 * Open Balance` 全科目 0 余额段（冗余但无害）。
- 元数据注释（method/orderId/type 等）是 split_huabei.py 两级匹配的依据，**生成脚本不得剥离**。
- 金额负号写法：`- 100.00 CNY`（负号与数字间有空格，hledger 兼容）。

## C2 `config/*.yaml`（deg 规则）

- **写方**：我们；**读方**：deg（`translate -p <provider> -t ledger --config <yaml>`）
- **已确认语义**（2026-09-06 读 `reference/double-entry-generator` 源码 + 真实账单实测）：
  1. 规则按顺序逐条评估；规则内多条件 AND；匹配为"包含"（`fullMatch: true` 为精确，防 `余额` 误伤 `余额宝`）。命中即赋值，**后命中覆盖先命中（同侧）**——宽规则在前、具体规则在后；**严禁无条件兜底规则**（会覆盖一切；默认值机制已兜底）。
  2. `targetAccount`：支出/不计收支/`/` → 借方(plus)；收入 → 贷方来源(minus)。`methodAccount` 方向相反。
  3. 未命中落 `defaultMinusAccount: Assets:FIXME` / `defaultPlusAccount: Expenses:FIXME`（FIXME=待确认队列，设计特性）。
  4. `status` 可匹配状态字段；`ignore: true` 命中即丢弃并终止匹配。
  5. **alipay**：退款（`退款-`前缀/category=退款/status=退款成功）自动交换借贷两侧；`退款成功`+category=退款 且原单可配（单号前缀+等额）→ 原单退款双剔除；`交易关闭`+不计收支 自动剔除；`已撤销` 不过滤（须 L0 ignore）。
  6. **wechat**：退款是独立收入行（txType=`XX-退款`），不自动配对——L0 丢弃退款行+`已全额退款`原单（净额归零）；部分退款原单保留全额（差额人工调）。`零钱提现`被 deg 强制为收入方向（method=入账银行）。备注含"服务费"自动拆手续费到 `defaultCommissionAccount`。
  7. **wechat 未收录交易类型**（如 `理财通赎回`）须加 CLI 参数 `--ignore-invalid-tx-types`；规则按原始文本匹配（finance.py import 已内置）。
  8. 账单"收/付款方式"在资金转出类行（余额宝-转出到银行卡、零钱提现、理财通赎回）是**目的地**而非来源——须用 L6 矫正层（item/txType 规则晚于 method 规则）。
  9. 分层顺序：L0 状态丢弃 → L1 宽 type → L2 分类/txType → L3 具体 item/peer → L4 猜测性 methodAccount → L5 权威 method → L6 方向矫正。
- provider 现状：`alipay` `wechat` 已配并对真实账单收敛（FIXME 口径见 STATUS）；`ccb/icbc/cmb/ceb` 待真实银行明细到位后配置（P1.4 暂缓）。

## C3 花呗账单证明 PDF（split_huabei.py 输入）

- 路径与打开密码：见本地 `docs/本地敏感信息_DO_NOT_COMMIT.md`（不入库）。
- 结构（2026-09-06 实测，17 页）：2026-02 ~ 2026-09 八个 `YYYY年MM月_花呗账单` 分段；每行 = 时间（日期+跨行秒）、名称、状态、金额、手续费。
- 名称形态：常嵌美团 26 位单号（对应支付宝商家订单号）；`**单号XP...` 为脱敏单号；特殊行：`自动还款 -X`、`退款还款 -X`。
- 匹配策略：美团 26 位单号精确 > 日期+金额+名称模糊；未匹配 → FIXME 清单。
- **文件含身份证号，仅本地使用，勿提交、勿外发。**
