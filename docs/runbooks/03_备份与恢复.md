# 备份与恢复（加密归档）

> 目标：`journals/raw/reports/close/config/paisa.db` 这些 **gitignore 的敏感数据**也能防误删、防磁盘故障；
> 主仓库与账本仓（journals/.git）只覆盖 journals 的一部分，**不能替代本方案**。

## 1. 备份策略（三层）

| 层 | 内容 | 频率 | 位置 |
|---|---|---|---|
| L1 本地 git | 主仓（代码/文档/配置模板）+ 账本仓（journals） | 每次改动（SOP 步骤 5） | 本机 |
| L2 加密归档 | **全部敏感数据**：journals、raw 账单、reports、close、config、paisa.db、敏感信息文件 | 每月 SOP 后 + 任何破坏性操作前（如 `reset_init.py`） | `backups/*.pcfobak` |
| L3 异地 | 把最新的 `.pcfobak` 复制到网盘/U盘（文件已加密，可安全外放） | 同 L2 | 用户自行 |

- 归档格式：AES-256-GCM，key = PBKDF2-HMAC-SHA256(密码, salt, 600k)；密码文件 `config/backup_secret.txt`（首次运行自动生成，gitignore，**绝不进归档**）。
- 保留策略：默认保留最近 10 份，自动清理更旧的。
- RPO≈1 个月（或每次重要操作前）；RTO≈5 分钟（见第 4 节恢复流程）。

## 2. 生成备份

```bash
cd <仓库根>
venv/Scripts/python scripts/backup.py backup
# 输出示例：文件 325 个 / 原始 22.2 MB → 归档 5.9 MB + sha256
```

- 首次运行会生成 `config/backup_secret.txt` 并提示：**立刻把密码抄进密码管理器**；密码丢失 = 归档永久无法恢复。
- 也可用 `--password` 或环境变量 `PCFO_BACKUP_PASS`（CI/脚本场景）。
- 查看本地归档：`venv/Scripts/python scripts/backup.py list`

## 3. 校验（恢复演练，建议每月做一次）

```bash
venv/Scripts/python scripts/backup.py verify backups/personalcfo-<ts>.pcfobak
```

它会：解密 → 解压到临时目录 → 对照清单逐文件校验 sha256 → 用还原出的 journals 跑
`hledger check balanced` → 打印结论并自动清理临时目录。
全部 ✅ 才算"备份可用"，任何一项 ❌ 都要重新生成备份。

## 4. 恢复

```bash
# 先校验
venv/Scripts/python scripts/backup.py verify backups/personalcfo-<ts>.pcfobak
# 恢复到临时目录（不直接覆盖现账本）
venv/Scripts/python scripts/backup.py restore backups/personalcfo-<ts>.pcfobak --to .planning/restore-<ts>
# 人工比对无误后，再替换：
#   - 整仓恢复：把还原目录内容拷回仓库根（先手工备份当前 journals/raw/...）
#   - 只恢复账本：拷 journals/*.journal 回去，然后
venv/Scripts/python src/finance.py check
venv/Scripts/python scripts/reconcile-check.py
vendor/paisa/paisa.exe update --config paisa_test/paisa.yaml    # 重新灌库
```

注意：
- `restore` 不会自动覆盖现有文件；目标目录非空需 `--force`。
- 恢复后 DB 建议用 `paisa update` 重建（`paisa_test/paisa.db` 也可直接从归档还原，但重建更干净）。
- Git Bash 下若提示信息乱码，先 `export PYTHONIOENCODING=utf-8`（或直接在 cmd 里跑）。

## 5. 接入月度 SOP

在 `01_月度SOP.md` 步骤 5（账本仓提交）之后加一步：

```bash
venv/Scripts/python scripts/backup.py backup
venv/Scripts/python scripts/backup.py verify backups/personalcfo-<最新>.pcfobak
```

破坏性操作前（重置初始化、批量改账本、升级 Paisa fork）**必须先做一次 backup**。

## 7. 代码 / Paisa fork 备份（P7.18）

Paisa fork 是独立 git 仓，**不在主仓库历史里**，单独备份：

| 资产 | 位置 | 内容 |
|---|---|---|
| 私有快照仓 | `https://github.com/bootition/PersonalCFO-paisa`（private，分支 `master`） | fork 源码树快照（提交 `a7515c4`，对应本地 `vendor/paisa@4897759`） |
| 完整历史 bundle | 同仓 Release `fork-2026-09-12` 资产 + 本地 `backups/paisa-fork-20260912.bundle`（6.18 MB） | 31 个 fork 提交的完整可达历史（浅历史，`git bundle verify` 通过） |
| 上游参照 | `git -C vendor/paisa remote -v` → `upstream` = ananthakumaran/paisa | 升级/diff 用 |

恢复 fork 历史：

```bash
git clone https://github.com/bootition/PersonalCFO-paisa.git paisa-restore   # 得到快照
# 或从 bundle 恢复带历史的仓库：
git clone backups/paisa-fork-20260912.bundle paisa-from-bundle
```

⚠️ 已知限制：本地 `vendor/paisa/.git` 是**浅克隆**且 gc 后有一个缺失对象，直接 `git push` 会
`index-pack failed`（远端收不到完整包）。**不要试图直接推 vendor/paisa**；备份走上面的快照 + bundle。
fork 里每次构建产物（`web/static`）不入 git，避免仓库再次膨胀。
